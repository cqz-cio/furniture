# 租户专属账号访问策略

`yudao.tenant.platform-visit-denied-tenant-ids` 是禁止平台超级管理员跨租户访问的租户编号集合，默认空集合，不改变其他租户的既有行为。

Trendz Green 使用租户 164。经授权发布本次 ERP 版本时，在生产 `config/backend.env` 现有 `SPRING_APPLICATION_JSON` 的 `yudao.tenant` 下合并：

```json
{"platform-visit-denied-tenant-ids":[164]}
```

保留其他 JSON 配置及该集合内原有编号。此配置须随新版后端启动生效；仅编辑配置文件、更新前端或删除账号不能替代后端发布。本次无数据库结构迁移。

- 平台超级管理员发送 `visit-tenant-id: 164` 访问租户业务接口时返回业务状态码 403。
- 直接篡改 `tenant-id` 仍由已有租户安全过滤器拒绝。
- 本租户账号正常访问自己的 CMS 和询价数据。公开登录租户选项和官网已发布内容保留。
- `/system/tenant/visit-list` 只返回当前平台账号获准访问的租户。登录页继续使用 `simple-list`。
- 前端在加载菜单、字典和业务页面之前验证旧的访问租户缓存。失去访问权时清除访问租户和旧权限缓存。
- 账号资料、登录权限及注销接口使用登录租户上下文，避免旧访问租户导致无法退出或身份信息错位。

发布须沿用生产 CD：本地测试 → CI 构建 → 测试 CD → 生产 preflight → 生产发布 → 正反向验收。不得把本地已通过测试当作线上已生效。

验收至少覆盖：租户 164 自己的账号可用、平台访问 164 被拒绝、其他租户访问规则不变、旧缓存无法继续访问、公开产品正常读取。若回退到不支持该策略的旧镜像，访问限制会失效；回退前必须评估并明确告知。

本地 Mockito 若在动态附加 Java agent 时停滞，终止整个测试进程树，使用已安装的 Byte Buddy agent 在测试 JVM 启动时加载，避免重复运行相同的挂起命令。仅此测试参数用于本地验证，不修改生产 JVM。
