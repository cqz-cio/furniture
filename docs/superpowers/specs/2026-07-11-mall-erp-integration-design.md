# 商城与 ERP 集成设计

## 目标

将租户 `121` 的家具商城与 ERP 产品、库存、销售和退货流程完整对接，同时保留商城在商品图片、营销文案、会员价格、购物车、支付和会员体验方面的职责。

对接完成后，商城网页继续使用适合消费者访问的商城接口；ERP 作为产品基础资料、成本和真实库存的主数据系统，由后端集成层负责同步与流程编排。

## 当前状态

- 商城网页使用 `/app-api/product/*`、`/app-api/trade/*`、`/app-api/member/*` 和 `/app-api/system/*`。
- 商城网页没有调用 `/erp/*` 接口。
- 项目包含 ERP 产品、分类、单位、仓库、库存、销售订单、出库和销售退货的服务端代码及管理端 API 定义。
- 当前本地数据库只有 `product_*` 商城商品表，没有初始化任何 `erp_*` 表。
- 租户 `121` 当前有 26 个商城 SPU 和 26 个默认 SKU。

## 方案选择

采用后端同步与编排方案，不允许商城浏览器直接调用 ERP 管理端接口。

原因：ERP 接口需要管理端权限，数据模型不包含商城图片、营销文案、会员价、购物车和在线支付语义。由网页直接组合两套接口会暴露权限、产生跨系统不一致，并使结算库存校验缺乏原子性。

## 主数据边界

### ERP 负责

- 产品编码和条码
- 基础产品名称
- 产品分类与计量单位
- 采购成本
- 仓库与实际库存
- 销售订单、销售出库与销售退货
- 库存变动明细

### 商城负责

- 商品主图和详情图库
- 营销标题、关键词、介绍和详情内容
- 市场价、零售价、会员价和促销规则
- 上下架状态与商城排序
- 购物车、结算、在线支付和会员订单视图
- 会员账号、收货地址和会员权益

### 共享但有明确主方

- 商城展示名称默认同步 ERP 基础名称，商城允许配置独立营销标题。
- 商城 SKU 成本价由 ERP 覆盖，不能在商城侧反向覆盖 ERP。
- 商城可售库存由 ERP 实际库存减去商城有效占用量计算。
- 商城零售价不自动覆盖 ERP 产品成本或 ERP 销售参考价。

## 数据模型

新增商城 ERP 映射表，禁止依赖名称或数组顺序匹配。

`mall_erp_product_mapping`：

- `id`
- `tenant_id`
- `mall_spu_id`
- `mall_sku_id`
- `erp_product_id`
- `erp_product_code`
- `sync_status`：`PENDING`、`SYNCED`、`FAILED`、`DISABLED`
- `last_synced_at`
- `last_error`
- `version`
- 标准创建、更新、软删除字段

唯一约束：

- `(tenant_id, mall_sku_id, deleted)` 唯一
- `(tenant_id, erp_product_id, deleted)` 唯一
- `(tenant_id, erp_product_code, deleted)` 唯一

新增业务单据映射表 `mall_erp_order_mapping`：

- `tenant_id`
- `mall_order_id`
- `mall_order_no`
- `erp_sale_order_id`
- `erp_sale_order_no`
- `sync_status`
- `last_synced_at`
- `last_error`
- `version`
- 标准创建、更新、软删除字段

商城订单 ID 与 ERP 销售订单 ID 在同一租户内分别唯一。

新增同步日志表 `mall_erp_sync_log`，记录实体类型、实体 ID、方向、事件类型、幂等键、请求摘要、结果、错误和重试次数。日志不保存密码、令牌、会员完整地址或支付敏感信息。

## 第一阶段：商品与库存

### ERP 初始化

- 将官方 ERP 数据表结构加入本地基础设施初始化流程。
- 为租户 `121` 创建默认产品单位、产品分类和默认仓库。
- 将现有 26 个商城默认 SKU 初始化为 26 个 ERP 产品。
- 产品编码使用稳定规则，例如 `RH-121-<mallSkuId>`；重复执行不会创建重复产品。
- 初始化映射表并验证 26 个商城 SKU 全部具有唯一 ERP 产品映射。

### 商品同步

- ERP 产品创建或更新后，集成服务更新对应商城 SPU/SKU 的基础名称、成本价和有效状态。
- 商城图片、营销介绍、市场价、会员价、排序和详情配置不被 ERP 同步覆盖。
- ERP 产品禁用时，商城商品不直接删除；映射标为 `DISABLED`，商品进入不可购买状态并由管理人员决定是否下架。
- 提供单商品同步、全量同步和失败重试管理端接口。

### 库存同步

- ERP 仓库库存是实际库存主数据。
- 商城可售库存等于启用仓库可用库存总和减去商城有效库存占用。
- 商品列表和详情仍通过商城商品接口返回库存，但返回值由集成库存服务计算或同步。
- 加入购物车只做即时可用性提示，不产生库存扣减。
- 结算和下单必须重新校验可售库存。
- 支付或订单确认阶段按现有交易语义产生库存占用；取消、超时或退款按规则释放。
- ERP 出入库完成后发布库存变化事件，更新商城 SKU 库存并写入同步日志。

## 第二阶段：订单与履约

### 商城订单到 ERP

- 商城订单支付成功后触发 `MALL_ORDER_PAID` 集成事件。
- 以 `tenantId + mallOrderId + MALL_ORDER_PAID` 作为幂等键。
- 根据会员资料创建或匹配 ERP 客户；只传递履约所需的最少信息。
- 根据商品映射生成 ERP 销售订单和明细。
- ERP 销售订单创建成功后写入单据映射表。
- ERP 临时失败不回滚已经成功的支付；记录失败并通过重试任务补偿。

### ERP 履约到商城

- ERP 销售订单审核、出库和作废状态映射到商城履约状态。
- 商城订单支付状态仍由支付模块负责，ERP 不得改变支付事实。
- ERP 出库完成后写入发货或履约信息，并触发商城订单状态更新。
- 重复回调必须通过单据映射与版本检查保持幂等。

### 退款与退货

- 商城退款申请成功后，按是否已出库决定仅退款或创建 ERP 销售退货。
- ERP 销售退货入库完成后增加实际库存，并同步商城可售库存。
- ERP 单据作废时需要写入同步日志并恢复对应状态，不能重复回补库存。

## 网页与接口边界

| 网页功能 | 网页调用 | ERP 对接方式 |
|---|---|---|
| 商品列表、详情 | 商城商品接口 | 服务端合并 ERP 名称、成本状态和库存 |
| 购物车 | 商城购物车接口 | 加购、改数量时校验 ERP 可售库存 |
| 结算 | 商城结算接口 | 结算时重新读取 ERP 可售库存 |
| 下单、支付 | 商城交易与支付接口 | 支付成功异步创建 ERP 销售订单 |
| 订单列表、详情 | 商城订单接口 | 返回 ERP 履约状态摘要 |
| 退款退货 | 商城售后接口 | 服务端创建 ERP 销售退货并同步库存 |
| 登录、会员、地址 | 会员接口 | 不接 ERP |
| 商品图片和营销内容 | 商城商品接口 | ERP 不覆盖 |

商城浏览器不保存 ERP 管理端令牌，不调用 `/admin-api/erp/*`。

## 服务边界

后端增加独立的商城 ERP 集成服务，核心接口包括：

- `syncProductFromErp(tenantId, erpProductId)`
- `syncAllProductsFromErp(tenantId)`
- `calculateSellableStock(tenantId, mallSkuId)`
- `validateSellableStock(tenantId, items)`
- `createErpSaleOrder(tenantId, mallOrderId)`
- `syncFulfillmentFromErp(tenantId, erpSaleOrderId)`
- `createErpSaleReturn(tenantId, mallAfterSaleId)`
- `retryFailedSync(syncLogId)`

调用方只依赖上述业务接口，不直接跨模块操作对方数据表。

## 一致性与失败处理

- 跨商城与 ERP 的操作使用最终一致性，不尝试跨模块分布式数据库事务。
- 每个集成事件都有稳定幂等键。
- 同步失败写入日志，保存简短错误信息和重试次数。
- 自动重试使用有限次数和退避策略；超过阈值进入人工处理状态。
- 商品或订单找不到映射时禁止静默跳过，必须记录明确失败。
- 库存不足时结算或下单返回可理解的商品级错误，不生成负库存。
- 同步任务始终限定当前租户，禁止租户 `121` 与租户 `1` 之间建立映射。

## 管理与可观测性

- 商城商品后台显示 ERP 产品编码、映射状态、ERP 库存和最后同步时间。
- ERP 产品后台显示对应商城 SKU 与商城上架状态。
- 提供同步日志列表、失败原因、单次重试和批量重试。
- 提供数据审计：无映射商品、重复映射、库存差异、成本差异、孤立订单映射和失败事件。

## 测试与验收

### 第一阶段

- ERP 表结构可重复初始化。
- 租户 `121` 的 26 个商城 SKU 与 26 个 ERP 产品一一映射。
- ERP 修改名称和成本后，商城允许字段正确更新，图片与营销字段保持不变。
- ERP 入库、出库和盘点后，商城可售库存正确变化。
- 无映射、重复映射和跨租户映射均被拒绝并记录。
- 商品列表、详情、购物车和结算页面显示一致库存。

### 第二阶段

- 支付成功只生成一张 ERP 销售订单。
- 重复事件不会生成重复单据。
- ERP 审核、出库和作废状态正确回写。
- 退款退货只回补一次库存。
- ERP 暂时不可用时商城支付事实保留，同步进入可重试状态。
- 商城订单页面显示正确的 ERP 履约摘要。

## 实施顺序

1. ERP 表结构和租户 `121` 基础数据初始化。
2. 商品映射表、同步日志和商品同步服务。
3. ERP 库存汇总、商城库存校验和网页库存验证。
4. 订单映射与支付成功后的 ERP 销售订单同步。
5. ERP 履约状态回写。
6. 售后退货与库存回补。
7. 管理端同步状态、日志和人工补偿。
8. 全链路审计、回归测试和故障演练。

## 非目标

- 不让商城浏览器直接访问 ERP 管理端 API。
- 不将会员登录、收货地址、会员价或在线支付迁入 ERP。
- 不允许 ERP 同步覆盖商城图片和营销内容。
- 不清理租户 `1` 的现有测试商品。
- 不在缺少映射和幂等保护的情况下直接复制业务单据。
