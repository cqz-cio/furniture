# 商品目录数据与图片优化设计

## 目标

整理家具商城当前使用的“小租户”（`tenant_id = 121`）商品目录，使每款商品都具备独立且品类匹配的外部商品图、合理且可测试的商品信息，并确保后端目录不可用时本地 Demo 商品仍可正常展示。

## 已确认范围

- 仅优化租户 `121` 的家具商品、分类、品牌和 SKU 关联数据。
- 不修改租户 `1` 的重复商品，避免影响其他测试场景。
- 优化前检查订单、购物车等业务表对商品与 SKU 的引用。
- 延长租户 `121` 的有效期，使测试环境能够继续调用接口。
- 修复本地 Demo 商品的缺图问题。
- 最终验证商品列表、详情、购物车和结算所需的数据链路。
- 完成后提交并推送代码；数据库中的运行时修改通过可重复执行的脚本固化到仓库。

## 图片方案

采用轻量的外部图片方案，不将大批位图资源提交到 Git。

- 每款商品配置不同且符合商品类型的主图 URL。
- 详情图库配置与同一商品一致的多角度或场景图片；不使用同一 URL 重复填充图库。
- 图片统一使用 HTTPS，并带适合商品列表与详情页的尺寸和裁切参数。
- 图片来源选择稳定、允许公开访问的图片服务；URL 作为测试素材，不声称拥有商品或品牌版权。
- 前端图片组件在 URL 加载失败时切换到明确的商品占位状态，避免破图图标和布局塌陷。
- 数据审计脚本检查空图片、重复主图、无效协议、图库为空和主图未进入图库等问题。

## 商品数据规则

租户 `121` 保留 26 款覆盖主要家具品类的测试商品。每款商品满足以下约束：

- 名称为可读英文，不包含 `?` 乱码或空白名称。
- 关键词覆盖品类、材质、房间、风格和价格区间，方便搜索与 RAG 测试。
- 简介准确描述材质、造型和适用空间，不包含无法验证的认证或性能承诺。
- 分类与商品类型一致，品牌、分类、SPU 和 SKU 均属于租户 `121`。
- 金额单位使用分，并满足 `cost_price < price < market_price`。
- 库存为非负整数，并覆盖低库存、常规库存和充足库存场景。
- SPU 与默认 SKU 的图片、价格、市场价、成本价和库存保持一致。
- 商品状态为销售中；被现有订单或购物车引用的 SPU/SKU ID 不改变。

## 数据迁移与安全

实现一个可重复执行的 PowerShell 数据整理脚本，沿用项目现有种子脚本模式。

1. 读取并验证租户 `121`、套餐、分类、品牌和商品状态。
2. 将租户有效期延长到适合本地长期测试的日期。
3. 按现有 SPU ID 更新商品信息，不删除、不重建已有商品。
4. 按现有 SKU ID 同步默认 SKU 数据，保留业务引用。
5. 执行后输出商品总数、缺图数、乱码数、价格异常数、分类/品牌跨租户数和 SKU 不一致数。
6. 任一关键校验失败时以非零状态退出，便于开发者发现初始化问题。

脚本不得修改租户 `1`，不得清空商品、订单、购物车或会员数据。

## 前端行为

- 联机状态下，列表页使用租户 `121` API 返回的商品和图片。
- API 请求失败或目录为空时，页面继续使用本地 Demo 商品；这些商品必须拥有有效主图和图库。
- `ProductImage` 负责图片加载失败回退；列表、购物车、订单和结算页面共享该行为。
- 商品详情模型优先使用数据库图库，并在图库数量不足时使用有语义的占位项，页面不崩溃。
- 图片使用延迟加载，保持现有页面布局和响应式尺寸。

## 测试与验收

- 单元测试覆盖商品映射、Demo 图片完整性和图片加载失败回退结构。
- 数据审计覆盖 26 款租户 `121` 商品，要求：缺图为 0、乱码为 0、价格异常为 0、分类/品牌跨租户为 0、默认 SKU 不一致为 0。
- 手工或浏览器验证商品列表、商品详情、加入购物车和结算商品缩略图。
- 在后端不可用的情况下验证本地 Demo 目录仍然每款有图。
- 运行前端完整测试套件，确认现有会员、结算与订单流程不受影响。

## 非目标

- 不清理租户 `1` 的重复家具商品。
- 不重做商品列表或详情页视觉设计。
- 不为商品建立复杂多规格体系；本次保持现有默认 SKU 模式。
- 不将外部测试图片下载并提交到仓库。
