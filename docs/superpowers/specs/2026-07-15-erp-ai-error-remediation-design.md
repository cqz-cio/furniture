# ERP 与 AI 模块错误修复设计

## 背景

当前本地运行方式同时启动单体 `yudao-server`（48080）和独立 `ai-server`（48090）。单体已经包含 `system`、`infra`、商城和 ERP 等模块，但独立 AI 服务仍按微服务名称调用 `system-server` 和 `infra-server`。本地没有启动这些独立服务，因此 AI 页面读取数据时出现 `UnknownHostException`，前端统一显示“服务器错误，请联系管理员”。

浏览器与日志巡检还确认了以下独立问题：

- AI 绘画页面并发加载模型列表和作品列表，失败后会连续显示两个错误提示。
- XXL-Job 管理端未运行，AI 执行器每 30 秒注册失败。
- AI 音乐播放器把字符串时间、0 到 100 的音量和只读媒体属性直接绑定到 `<audio>`。
- 商城首页及统计页面把格式化金额字符串传给只接受数字的组件，并使用了 ECharts 已废弃的配置层级。
- 外部模型 API Key 和地址验证服务凭据尚未配置。

## 目标

- 本地只需一个命令启动一个 Java 后端进程。
- AI、商城和 ERP 接口统一由 48080 提供。
- AI 列表和管理页面不再出现通用服务器错误。
- 未配置外部模型或地址服务时显示明确、可操作的提示，不伪造成功结果。
- 本地日志不再持续出现无效的 XXL-Job 注册错误。
- 修复已确认的 AI 音乐播放器和商城统计前端警告。
- 保留生产环境与完整微服务部署能力，不把本地降级配置带入生产。

## 不在本次范围内

- 自动生成或写入真实模型 API Key。
- 自动开通 Google 地址验证、Suno、Midjourney 等第三方账号。
- 把整个项目改造成完整微服务本地集群。
- 修改与本次错误无关的功能、数据或用户未提交文件。

## 方案选择

### 采用：把 AI 模块并入单体服务

在 `yudao-server` 中增加 `yudao-module-ai-server` 依赖。单体已经排除了 OpenFeign RPC 客户端并加载 `system`、`infra` 等本地模块，因此 AI 的认证、错误日志和业务调用都在同一 Spring 进程中完成。

前端开发代理不再把 `/admin-api/ai/**` 单独转发到 48090，所有后台接口统一转发到 48080。一键启动和关闭脚本只管理 `yudao-server`。

### 未采用：保留两个后端并覆盖 Feign 地址

该方案可以把 `system-server` 和 `infra-server` 指向单体 48080，但仍保留混合架构和两个进程。未来新增 RPC 依赖时还可能再次出现同类问题。

### 未采用：启动完整微服务集群

完整集群需要 gateway、system、infra、product、AI 等多个进程，维护成本和启动时间都明显增加，不符合本地一键启动目标。

## 组件设计

### 后端单体整合

- `yudao-server/pom.xml` 引入 `yudao-module-ai-server`。
- 构建脚本只构建单体及其依赖，不再单独构建 AI 可执行包。
- 启动脚本只启动 48080，并在健康检查后验证代表性的商城和 AI 路由可访问。
- 停止脚本兼容清理旧版 `ai-server` 状态文件和残留进程，避免升级后端口占用。

### 本地任务调度

- 仅在 `local` 配置中默认设置 `xxl.job.enabled=false`。
- 生产和微服务配置保持原状。
- 需要 Suno、Midjourney 异步任务时，开发者可以在已部署 XXL-Job 管理端后显式覆盖为 `true`。
- 页面在没有相应模型时不允许提交异步任务，因此关闭本地执行器不会伪装第三方任务已经可用。

### 模型未配置时的处理

- 模型列表为空时，生成入口保持禁用或在提交前阻止请求。
- 页面显示“请先在 AI 控制台配置模型和 API Key”。
- 后端业务异常保留明确错误码和消息；前端不得把“未配置模型”改写为“服务器错误”。
- 不在仓库、日志或测试中保存真实 API Key。

### AI 音乐播放器

- `<audio>` 只绑定合法的 HTML 媒体属性。
- 播放状态通过 `play()`、`pause()` 和媒体事件同步，不写入只读的 `paused`、`duration`。
- `currentTime`、`duration` 和 `volume` 在状态层使用数字；展示时再格式化为 `mm:ss`。
- 音量滑块在 0 到 100 之间展示，写入媒体元素时除以 100 转成 0 到 1。
- 本地资源提供默认封面，避免依赖外部示例图片。

### 商城统计警告

- 数字卡片接收数值，货币格式仅在渲染层处理。
- ECharts 的 `axisLabel.textStyle` 属性提升到 `axisLabel` 直接配置。
- 不改变后端统计口径和页面显示精度。

### 地址验证降级

- 未配置外部地址验证凭据时继续使用已有本地/后端标准化。
- 保留“兜底模式”警告，明确不能证明街道可投递。
- 不把兜底结果标记为外部验证成功。

## 数据流

本地前端请求 `/admin-api/**`，Vite 统一转发到 48080。`yudao-server` 在同一进程内完成 Token 校验、AI 业务处理、商城/ERP 查询和错误日志写入。只有实际调用已配置模型时，才访问第三方模型服务。

## 错误处理

- 认证或权限失败使用已有明确业务错误，不返回 DNS/RPC 异常。
- 模型缺失返回可操作的配置提示。
- 外部服务不可用时保留具体平台信息，但不泄露密钥。
- 前端页面加载失败时只显示一次与失败请求对应的提示，避免缓存页面产生重复通用弹窗。

## 测试与验收

### 自动化验证

- 后端：验证 `yudao-server` 能加载 AI 控制器和本地 `system`、`infra` 实现；运行相关 Maven 测试。
- 脚本：验证一键启动只管理 48080，旧 AI 进程能被安全清理，健康检查失败时返回非零状态。
- 前端：为音乐播放器数值转换和模型缺失提示增加测试；运行类型检查和相关单元测试。
- 配置：验证 `local` 关闭 XXL-Job，其他 profile 不受影响。

### 浏览器回归

只读检查以下页面不出现“服务器错误”：

- AI 对话、绘画、写作、音乐、知识库、工作流、思维导图。
- 模型配置、绘画管理、音乐管理、写作管理、导图管理。
- 商城首页、商品列表、分类、品牌、属性、评论、订单、售后和商品统计。

不执行会产生外部费用或修改业务数据的生成、同步、删除操作。模型未配置时验证页面显示明确配置提示。

## 兼容性与回滚

- 独立 `ai-server` 代码和微服务启动脚本仍保留，完整微服务部署不受影响。
- 本地总启动脚本改为单体模式；如需恢复混合运行，可回滚启动脚本、代理配置和单体 AI 依赖这三组改动。
- 所有变更提交到 `codex/agent-rag`，不修改 `main`。
