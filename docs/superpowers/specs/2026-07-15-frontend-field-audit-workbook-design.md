# Oakved 前端页面字段审计清单设计

日期：2026-07-15

## 1. 目标

重新制作一份供产品经理直接使用的 Excel，盘点 Oakved 家具商城顾客端与 Yudao ERP 管理端中真实可见、可输入、可选择或可操作的前端内容，并指出与北美家具电商项目画像不匹配、需要确认或需要补齐的部分。

本次不把 Java、API、DTO、DO、数据库列、环境变量或服务层常量作为主清单记录。它们只能作为某个前端问题的技术出处或依赖，放入附录。

## 2. 已确认范围

### 2.1 家具商城顾客端

覆盖全局导航、首页、商品列表、商品详情、购物车、登录与账户、地址、结账、支付、订单，以及 Membership、Trade、Gift Registry、SEO 和 AI 导购相关的可见界面与交互状态。

### 2.2 ERP 管理端

覆盖与 Oakved 电商运营直接相关的菜单和页面，包括商品、SKU、类目、订单、支付、配送、仓库与库存、会员、Membership、Trade、Gift Registry、促销、经营看板和相关配置界面。

通用开发工具、基础设施控制台及与 Oakved 运营无直接关系的 Yudao 模块不进入主清单；如它们会直接暴露在菜单中，则以“应隐藏或移除的菜单项”记录。

## 3. 行级定义

主清单的一行代表一个产品经理能够在页面上找到的界面元素或交互状态，例如：

- 页面标题、区块标题和说明文字；
- 输入框、下拉框、单选、多选、日期、上传和开关；
- 按钮、链接、菜单项和操作入口；
- 表格列、筛选项、状态标签和金额展示；
- 表单校验、空状态、错误提示、成功提示和禁用状态；
- 商品规格、价格、税费、支付、配送和库存等用户可见信息。

仅存在于代码、接口或数据库中而没有前端表现的字段不作为独立行。

## 4. 审计方法

采用“静态全量盘点 + 关键链路运行复核”：

1. 从路由、菜单配置和页面目录建立页面覆盖清单；
2. 从 Vue 模板、组件和 i18n 文案提取可见元素；
3. 按页面入口和用户流程归类，不按技术文件顺序排列；
4. 对商品详情 → 购物车 → 结账 → 支付 → 订单，以及 ERP 商品 → 订单 → 支付 → 履约页面进行运行态抽查；
5. 每条记录保留精确源码路径和 1-based 行号；
6. 旧版技术审计记录只用于补充判断依据，不直接复制进新版主清单。

## 5. Excel 结构

### 5.1 `01_前端总清单（打开即看）`

汇总两个前端中需要处理的界面项。按“改造时点 → 是否影响真实付费闭环 → 端别 → 用户流程”排序，打开文件即可看到核心问题。

主表字段：

1. 编号
2. 端别
3. 怎么进入
4. 页面名称
5. 页面区域
6. 元素类型
7. 当前界面显示或可操作内容
8. 当前问题
9. 为什么不适合 Oakved
10. 建议改成或达到的效果
11. 是否影响真实付费闭环
12. 改造时点
13. 产品经理需要决定什么
14. 处理状态
15. 产品决策或备注

### 5.2 `02_家具商城页面`

只包含顾客端页面元素，按全局导航 → 商品列表 → 商品详情 → 购物车 → 结账 → 支付 → 订单 → 账户 → 增值服务排序。

### 5.3 `03_ERP管理界面`

只包含 ERP 中员工能看到或操作的界面元素，按菜单模块和日常运营流程排序。

### 5.4 `04_真实付费闭环`

汇总会直接阻断或影响商品真实下单与支付的前端问题，供第一阶段优先处理。

### 5.5 `05_上线前增值服务`

汇总 Membership、Trade、Gift Registry、SEO 和 AI 导购等正式上线前必须稳定运行、但不抢占当前核心闭环的界面项。

### 5.6 `06_技术定位附录`

通过编号与主清单关联，包含页面路由、Vue 组件、i18n key、技术字段、源码路径、行号和必要的后端依赖说明。产品经理无需阅读本表也能理解主清单。

### 5.7 `07_覆盖范围`

列出已扫描页面、页面入口、源码目录、是否发现问题和未能运行复核的原因，用于证明审计边界。

## 6. 判断与优先级

判断分类只使用通俗业务语言：

- 明确不适合：现有内容与 Oakved、北美市场或真实交易明显冲突；
- 需要业务确认：取决于首发市场、真实商品、支付、税费、仓库或运营规则；
- 可以保留但需完善：大框架可用，内容、文案或国际化仍需补齐。

改造时点：

- 现在：直接影响商品页面到真实付费订单闭环；
- 正式上线前：Membership、Trade、Gift Registry、SEO、AI 导购及上线必需的运营能力；
- 后续优化：不阻断上线的体验或效率优化。

## 7. 可追溯性与质量要求

- 每条主清单记录必须能通过编号关联到至少一个前端源码位置；
- 主清单不得出现以 API、VO、DTO、DO、数据库列或环境变量为主体的记录；
- 页面名称、区域和当前显示内容必须让产品经理能在界面上找到；
- 商城和 ERP 分表数量应与总表按端别汇总一致；
- 核心闭环和上线前增值服务分表应由总表筛选规则生成；
- Excel 不得包含公式错误或外部引用；
- 全部文字使用黑色，所有单元格使用纯白底，不使用黑色、灰色或彩色填充；
- 用粗体、字号、间距及黑色或浅灰色边框区分层级。

## 8. 验收标准

1. 打开第一张表不会看到后端模型或接口字段；
2. 产品经理能根据“怎么进入、页面名称、页面区域”在项目中找到对应界面；
3. 家具商城和 ERP 管理端均有独立、完整的页面清单；
4. 商品详情到真实支付订单的关键前端问题可单独筛出；
5. 每条记录都有明确问题、通俗原因、建议方向和源码出处；
6. 逐张工作表完成内容、公式、样式和可读性验证。
