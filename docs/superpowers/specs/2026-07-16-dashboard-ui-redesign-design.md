# Yudao ERP 数据看板 UI 改版设计

> 日期：2026-07-16  
> 状态：待用户书面确认  
> 范围：Figma 桌面端修改稿，不修改正式代码、接口、数据库和权限

## 1. 目标

为现有独立“数据看板”导航制作一份经营结果优先的桌面端 UI 修改稿，使运营人员进入页面后能快速回答三个问题：

1. 当前销售、订单、利润和转化表现如何；
2. 与上一周期相比是增长还是下降；
3. 哪些商品或数据问题需要立即处理。

修改稿沿用现有 Yudao 管理后台的信息结构和 Element Plus 可实现能力，视觉参考 shadcn Dashboard：白色背景、黑灰文字、浅灰边框、轻量阴影、紧凑卡片和克制的状态色。

## 2. 用户与使用场景

- 主要用户：家具电商运营人员。
- 次要用户：商品管理、财务查看角色和管理者。
- 默认场景：进入看板后查看截至昨日的近 30 个完整自然日，并与上一等长周期比较。
- 高频任务：查看核心经营结果、切换日期、筛选商品、定位高退款或低转化商品、查看利润质量、导出当前筛选数据。

## 3. 页面结构

### 3.1 紧凑页头

- 页面标题“数据看板”和一句简短说明。
- 显示可读的“数据截至时间”、更新延迟和覆盖状态。
- 右侧提供刷新、普通导出和有权限时的利润导出。
- 取消现有占用较高的宣传式标题卡，释放首屏高度。

### 3.2 筛选工具栏

- 数据范围：全站经营 / 商品分析。
- 日期：今日、近 7 日、近 30 日、近 90 日、自定义日期。
- 对比：对比上一等长周期。
- 商品分析范围增加分类树选择、商品名称/SPU/SKU 搜索和经营风险筛选。
- 展示已生效筛选标签，并提供“一键重置”。
- 切换分类导致原商品失效时，清除商品条件并给出明确提示。

### 3.3 数据质量状态条

- 将流量覆盖、PARTIAL、数据过期等重复提示合并为一条状态栏。
- 默认给出简短结论；展开后显示覆盖日期、数据延迟、受影响指标和原因。
- 有操作权限时提供“查看任务”或“立即重算”入口；Figma 稿只表现入口，不定义新增后端能力。
- 未知值显示“—”，不得显示为业务 0。

### 3.4 核心经营指标

首排固定显示六项结果指标：

1. 净销售额；
2. 支付订单；
3. 毛利润；
4. 毛利率；
5. 浏览至下单转化率；
6. 退款率。

每张指标卡包含当前值、与上周期的变化、单位和口径说明入口。利润无权限时不渲染利润卡，不使用遮罩或零值替代。

### 3.5 流量与转化摘要

第二排展示首页浏览量、首页访客数、商品详情浏览量、商品详情访客数、加购人数和支付买家。商品分析范围隐藏不可按商品归因的首页指标，并明确说明范围差异。

### 3.6 趋势与经营摘要

- 左侧约占三分之二：近 30 天浏览量、净销售额和毛利润趋势，可切换指标；保留数据表替代入口。
- 右侧约占三分之一：本周期增长、下降、数据质量和异常商品摘要。
- 更新时间使用 `Asia/Shanghai` 可读日期时间，不显示原始毫秒值。

### 3.7 运营任务

任务类型包括高浏览低转化、高退款、低毛利或负毛利、成本缺失。任务卡使用中文业务名称，展示严重度、触发原因、受影响指标、商品、建议动作和“查看商品”入口。技术枚举只作为次要说明，不作为主标题。

### 3.8 商品经营明细

- 默认列：排名、商品、详情 PV、支付订单、转化率、净销售额、毛利润、风险、操作。
- 提供“流量 / 销售 / 利润”三套列预设。
- 固定商品列和操作列，支持排序、分页、保存视图和导出当前结果。
- 其余成本、退款和质量字段通过列设置或行详情查看，避免默认展示约 19 列。

## 4. 指标文案规则

- “加购用户”仅用于去重用户数；事件次数必须写“加购次数”。
- “支付买家”仅用于去重买家数；订单数必须写“支付订单”。
- 转化率必须在说明中展示分子、分母和时间范围。
- 利润质量同时使用文字和图标表达，不只依赖颜色。
- COMPLETE、PARTIAL、EXACT、INCOMPLETE 等状态在界面中显示中文，英文枚举作为悬浮说明。

## 5. 视觉规范

- 画板基准宽度：1440px；内容区适配 Yudao 左侧导航后的可用宽度。
- 页面背景使用浅灰白，内容卡片使用白色。
- 主文字黑灰，次要文字中灰；蓝色只用于选中与主要操作。
- 危险和警告色仅用于确有风险的状态，不作为装饰。
- 卡片圆角约 10 至 12px，浅灰 1px 边框，阴影轻量。
- 使用紧凑的 8px 间距体系，保证首屏能看到核心指标和趋势上半部分。
- 设计稿使用可在 Figma 与前端稳定使用的中文无衬线字体。

## 6. 交互与状态

- 筛选变化时保留清晰的加载反馈，避免整页内容闪烁。
- 单个区块失败时原位显示错误和重试，不清空其他成功区块。
- 风险任务点击后切换到商品分析范围，写入对应筛选并定位商品表。
- 日期、数据范围、分类、商品或风险变化时分页重置为第一页。
- 导出按钮必须反映进行中、成功和失败状态。
- Figma 修改稿表现默认态、数据质量展开态和一个运营任务聚焦态；真实交互在代码实施阶段完成。

## 7. 响应式边界

本轮先交付 1440px 桌面端修改稿。桌面稿确认后再派生 390px 移动端稿，移动端必须满足：

- 筛选控件不超过容器宽度；
- 数据范围与日期分行；
- 对比开关独占一行；
- 页面左右安全边距不少于 16px；
- 表格改为核心列摘要与行详情，不强行压缩全部列。

## 8. 安全与权限边界

- Figma 使用示例经营数据，不放入真实客户、订单、Token、密钥或其他敏感信息。
- 设计稿不改变现有四类权限：基础查询、利润查询、普通导出、利润导出。
- 无利润权限时，利润字段在接口和界面都不存在；不能仅用 CSS 隐藏。
- 设计稿不新增数据采集、重算、导出或跨模块跳转权限；新增能力必须另行评审。
- UI 改版不修改既有指标口径、租户隔离、上海时区和数据质量规则。

## 9. Figma 交付内容

- 在现有 Figma 审计文件中新增页面“修改版｜桌面端”。
- 画板包含完整桌面端默认态，并保留原审计页面作为对照。
- 关键组件保持可编辑，包括筛选器、指标卡、状态条、趋势面板、任务卡和商品表。
- 完成后提供 Figma 直达链接和本地预览图。
- 交付前检查截图/图表无裁切、文字无溢出、间距一致、状态含义清楚。

## 10. 验收标准

- 首屏清楚展示六项核心经营结果和数据截至状态。
- 运营人员无需记忆分类 ID 或 SPU 即可理解筛选方式。
- 数据缺失、部分、延迟和过期状态不会被误认为 0 或正常。
- 风险提示能够回答“什么问题、影响谁、下一步做什么”。
- 商品表默认列不超过九个业务列，并可切换列预设。
- 设计在 1440px 画板上无重叠、裁切或不可读文字。
- 视觉可由现有 Vue 3、Element Plus 和 ECharts 技术栈实现，不依赖不适配的 React/shadcn 运行时代码。

## 11. 非本轮范围

- 不修改 Vue、Java、SQL、埋点、接口或权限代码。
- 不制作秒级实时大屏、渠道归因、拖拽报表或会计净利润。
- 不在本轮完成移动端正式稿或可点击的完整原型。
- 不保证 Figma 自动生成代码可以直接用于生产环境。
