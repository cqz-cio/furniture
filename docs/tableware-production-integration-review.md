正式 ERP 健康检查为 UP，当前发行版为 `cd-d22fa60a5d55ef700ad2ed29acf8ab5b3f6415bb-35177320622-1`，数据库 V053，没有失败迁移、进行中的发布或 Trendz Green 租户。主分支为 `17f139bcd7be8ea4b31f853b275af40bb2ac8e6e`。

- 使用现有维护密钥只读核对正式服务、发行记录和数据库结构；没有切换容器、Nginx、官网或正式数据库。
- 在正式服务器私有目录备份数据库，在临时副本中使用仅限该副本的账号演练 V054–V058，正式库始终保持 V053。
- 首次演练发现 V055 回填快照会触发文章 `update_time` 自动变化。已在这条尚未提交发布的迁移中显式保留修改时间，重新演练通过。
- 复测确认原有询价、文章、租户、角色授权等旧字段逐值哈希一致；产品、SKU、账号、附件数量及附件字节数保持不变；新增三个空业务表和十个菜单能力，未给现有角色增加权限。临时数据库和临时账号已删除。
- 本地联调库仅校准尚未发布的 V055 校验值，留存前后证据；已重建并重启成功。没有修复或改写正式 Flyway 历史。
- 已更新生成基线及 CI 测试名单，让餐具目录和运营服务测试进入既有发布流水线；十二项迁移/数据库流程测试通过。
- 网站适配器已准备显式 `erp-production` 模式，只接受 `https://api.vanzhome.com`，管理链接保留 `/admin/`；租户与密钥仍只由服务端配置。连接测试、网站构建和类型检查通过。
- 正式模式询价与隐私说明明确披露数据将进入正式 ERP；当前未启用正式模式，没有向正式 ERP 发送测试询价或创建餐具账号。

## 正式发布与接入步骤

1. 将本期 ERP 代码提交并推送，通过现有完整 CI、镜像构建和测试环境验收，取得不可变发行 ID。不得把本地 JAR 直接覆盖到正式容器，也不得伪造测试成功记录。
2. 将本次副本演练与该发行 ID、迁移文件 SHA256 和现在线上发行版绑定，登记正式流程需要的迁移兼容性审查；先执行生产 preflight。
3. 通过既有生产 CD 发布 ERP 后端和后台。该流程为单机切换，会有短暂不可用窗口；失败恢复遵循现有迁移兼容性规则，不用旧备份覆盖新的业务写入。
4. 经 ERP 管理 API 建立或核对正式 Trendz Green 租户，创建管理员、编辑、发布、销售和只读账号。正式租户 ID 以服务器返回值为准，不能复用本地编号或已有业务租户。正式密码与本地测试密码分开。
5. 配置站点、关闭联调邮件和站内通知；按内容账本导入产品、文章与素材，执行权限、发布、下载和单条明确标记的测试询价验收。
6. 验收通过后才把本地网站服务端配置切换为正式 ERP，并复查所有页面及后台跳转。官网仍不部署。

发布前证据位于工作区 `work/phase4-erp-integration/production-public-probe.json`、`production-migration-rehearsal.json`、`local-unreleased-migration-alignment.json` 和 `work/codex-logs/phase5` 对应时间戳日志。生产备份仅留在正式服务器私有演练目录，没有下载到公开仓库。

本报告不代表 CI/CD 已运行或正式接入已完成。尚未提交、推送、发布 ERP，也未切换网站连接。
