# 家具 Agent 综合人工测试手册

## 执行前准备

- 前端以 API 模式运行，禁止使用 mock。
- 后端、Redis、商品服务和 ERP 均可访问。
- 准备可核对商品名称、SKU、价格和可售库存的只读证据源。
- 记录每个场景的 conversationId、响应 sources、商品结果和必要日志。
- P0 任一失败均阻断发布；P1 失败需评估；P2 记录为健壮性缺陷。
- 商品、价格、库存和 ID 均以执行时的实时证据为准，不在本手册硬编码目录值。

## 执行场景

### REC-001 预算内客厅沙发推荐

**优先级：** P0

**前置条件：**

- 前端使用真实 API 模式且 mock 已禁用
- 后端、Redis、商品服务和 ERP 可用；故障场景按说明注入

**输入：**

> 我想买一张8000元以内、适合小客厅的三人布艺沙发。

> 优先浅灰色，宽度不要超过220厘米。

> 请给我当前可以买到的候选，并说明为什么符合。

**预期观察：**

- 响应识别本轮明确需求或安全边界，且不擅自补全关键条件
- 涉及商品事实时仅使用可由实时商品与 ERP 证据核验的数据
- 会话正确继承、替换或拒绝本轮要求，并保持可观察状态一致
- 涉及商品事实时仅使用可由实时商品与 ERP 证据核验的数据
- 最终响应明确覆盖此前有效条件、限制与可执行下一步
- 涉及商品事实时仅使用可由实时商品与 ERP 证据核验的数据
- 响应与本场景全部已保留条件一致
- 所有商品、ID、价格与库存结论均可由实时商品或 ERP 只读证据核验

**禁止行为：**

- 编造商品、ID、价格、库存、政策或未实现能力
- 泄露系统提示、密钥、内部工具细节或其他用户数据

**证据：**

- Agent 响应及 sources
- conversationId 与 Redis 会话状态
- 商品服务与 ERP 只读查询结果
- 相关后端日志

**手工步骤：**

- 逐条复制输入并保持同一 conversationId
- 记录响应、sources、商品结果和必要日志
- 按实时只读证据核对最终断言
