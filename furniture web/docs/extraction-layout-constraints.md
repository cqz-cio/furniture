# 源站抽取布局框架项目约束

本文档用于约束后续所有“参考源站 HTML/JSON 搭建抽取布局框架页”的工作。目标不是仿站、不是营销页复刻，而是把源站页面的布局结构、图片/视频投放区域、素材尺寸和来源关系可视化出来。

## 1. 先建抽取模型，再写页面

拿到源站 HTML、JSON、截图或其他资料后，不能直接开始写 Vue 页面。必须先整理抽取模型：

- JSON 中精确出现的图片节点。
- JSON 中精确出现的背景图节点。
- HTML/CSS 中声明但 JSON 未渲染出来的背景图。
- 视频、动效、iframe 或第三方媒体区域。
- 复合模块关系，例如“背景图 + 叠放图片 + SVG/Logo + 文案层”。
- 导航、footer、弹窗、追踪脚本等非主体内容是否排除。

如果抽取模型存在明显缺口，先说明缺口来源，而不是用页面实现掩盖。

## 2. 标注来源等级

每个图片/视频位必须标明参数来源，避免把精确数据和推断数据混在一起：

- `JSON rect 精确抽取`：来自 JSON 元素的 `rect`、`style.objectFit`、`src`、`backgroundImage`。
- `HTML background 声明`：来自 HTML/CSS 的 `background: url(...)`，但当前 JSON 未给出可见 rect。
- `按同类模块估算，待滚动抽取确认`：没有精确尺寸，只能根据同类模块或页面结构估算。

页面标注和数据对象里都应该保留这个来源信息。后续替换真实图片时，优先使用 `JSON rect 精确抽取` 的尺寸。

## 3. 按模块组织，不按孤立图片组织

源站页面常见模块不是单张图片，而是复合结构。必须以模块为单位表达：

- Hero 模块：通常是全宽图片或视频。
- Sourcebook 模块：可能包含背景图、封面图、Lockup 图、文案层和链接层。
- 系列模块：可能包含主视觉图、SVG 系列名、叠层文案。
- 半宽模块：通常左右并排，每边各有背景图或内容层。
- 横幅模块：会员、邮件注册、Sale 等通常是全宽背景图。

复合模块里的多张图片要说明它们属于同一整块视觉区域，不能展示得像互不相关的几张图片。

## 4. 尺寸策略

页面可视化必须尊重源站抽取尺寸：

- 有 JSON `rect` 时，使用实际显示尺寸作为主尺寸。
- 全宽模块按页面宽度展示，不放进会压缩宽度的普通文档容器。
- 半宽模块按左右并排展示。
- 叠层模块按原始 `x / y / width / height` 相对比例定位。
- 视频区域按抽取到的渲染尺寸或容器比例展示。
- 只有 HTML 背景声明时，必须标明“非精确 rect”，并用同类模块尺寸暂占位。

不要为了页面整齐统一而改变全宽、半宽、叠层关系。

## 5. 标注内容约束

每个媒体占位只保留对素材替换有用的信息：

- 模块名称。
- 参数来源等级。
- 页面显示尺寸。
- 来源文件或来源方式。
- 建议 2x 素材尺寸。
- 建议文件体积。
- 填充方式，例如 `cover`、`contain`、`fill`。

避免无效说明，例如“电脑端 1 个图片区域”。如果数量信息已经体现在模块结构或标题里，不要重复显示。

## 6. 不只依赖 JSON summary

不能只看 JSON 的 `summary.images` 和 `summary.backgroundImages` 就判断页面图片数量。必须同时检查：

- HTML/CSS 中的 `background: url(...)`。
- `content/dam`、`is/image`、`is/content`、`rhis` 等资源路径。
- `authoringname`、AEM component 名称、模块名称。
- 懒加载图片、未进入当前滚动视窗的模块。

如果 JSON 与 HTML 的图片数量不一致，以“可见精确数据 + HTML 声明补充数据”的方式合并，而不是二选一。

## 7. 优先做全页滚动抽取

如果需要更高精度，优先重新抽取：

1. 打开源站页面。
2. 自动滚动到底。
3. 等待懒加载图片、视频封面和背景图完成。
4. 再导出完整 JSON。
5. 对比初始 JSON 与滚动后 JSON 的新增媒体节点。

只有在无法重新抽取时，才根据 HTML/CSS 声明补充估算模块。

## 8. 页面实现约束

实现抽取框架页时：

- 页面是“抽取模型的可视化”，不是源站营销页复刻。
- 顶部导航可以保留项目已有导航，但不能遮挡抽取内容。
- 媒体占位应体现源站模块宽高关系。
- 复合模块可叠放多个占位，但必须保持整体模块尺寸。
- 不要把所有模块强行放进同一个窄容器。
- 不要引入与抽取无关的装饰、假图形或营销文案。

## 9. 验收清单

每次交付前必须检查：

- 源站主体图片/视频模块是否都列入抽取模型。
- JSON 精确节点和 HTML 补充节点是否区分清楚。
- 全宽、半宽、叠层模块是否按原网页关系展示。
- 参数标注是否有用、简洁、来源明确。
- 页面是否没有横向溢出。
- `npm.cmd run build` 通过。
- `npm.cmd run test` 通过。
- 浏览器视觉检查至少覆盖首屏、中段复合模块、后续模块。

## 10. 本次 Baby & Child 经验沉淀

本次 RH Baby & Child 页面暴露的问题：

- 一开始把需求做成仿站营销页，而不是抽取框架页。
- 过度相信 JSON `summary`，漏掉 HTML/CSS 中声明的后续背景图。
- 把 Sourcebook 这类复合模块表达得像孤立图片。
- 全宽模块被放进窄容器，导致显示尺寸不符合源站。
- 标注信息重复、位置干扰视觉理解。

后续同类工作必须先合并 HTML 与 JSON，形成完整抽取模型，再实现页面。页面上的每个尺寸和图片位都应能追溯到 JSON 精确数据、HTML 声明，或明确标注为估算。
