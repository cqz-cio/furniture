# 图片与视频素材需求清单

> 用途：给设计、拍摄、修图、视频和前端同事统一收图标准。  
> 当前版本：整理版，生成日期 2026-05-27。  
> 重要说明：这份清单不是最终上线素材表，而是“按源站结构准备素材”的工作清单。真实产品图到位后，还需要按页面效果再复核一次裁切、压缩和主体位置。

## 1. 阅读规则

| 状态 | 含义 | 使用方式 |
| --- | --- | --- |
| 已测 | 来自源站 JSON、outerHTML 或页面测量 | 可以作为当前规格参考，后续只需按真实图片视觉再微调 |
| PC 已测 | 目前只拿到桌面端规格 | 可以先准备桌面端图，移动端等 mobile JSON 或截图补齐 |
| 截图推断 | 来自首页长截图或人工视觉判断 | 只能先占结构，不要把尺寸当成最终规范 |
| 待补 | 目前只有导航或页面占位，没有完整源站页面数据 | 暂不安排最终修图，只先建文件夹和命名规则 |

## 2. 通用交付规范

| 项目 | 详细要求 |
| --- | --- |
| 图片格式 | 页面大图、商品图、分类图优先交付 WebP；如果需要二次精修，保留 JPG/PNG 源图。Logo、系列名、品牌 lockup 优先 SVG，无法 SVG 时用透明 PNG/WebP。 |
| 视频格式 | 视频本体单独交付 MP4 或 WebM，同时必须给 poster 封面图。poster 不要直接从压缩视频里截糊图，最好由原始素材导出。 |
| 尺寸规则 | 表中“显示尺寸”是页面实际渲染尺寸；交付建议按 2x 导出。例如显示 1350 x 900，就交付 2700 x 1800。 |
| 裁切规则 | 主体家具不要贴边；左右至少留 6%-10% 安全区，顶部保留文案空间；移动端图片要单独裁切，不要直接用 PC 图硬缩。 |
| 文件命名 | 建议使用 `页面-模块-端-序号-描述.webp`。例如 `home-hero-desktop-01-outdoor-lounge.webp`、`sale-category-mobile-03-bedroom.webp`。 |
| 压缩标准 | Hero/大场景图控制在 250-900KB；普通 banner 90-520KB；商品卡图 40-260KB；swatch 小样 4-35KB。最终以清晰度为准，不要为了体积牺牲质感。 |
| 信息标注 | 每张图至少标注：页面、模块、PC/Mobile、显示尺寸、交付尺寸、素材来源、状态、是否可裁切、是否含文字。 |

## 13. 给图片团队的执行建议

- 第一批先做 Sale、Baby & Child、Outdoor，因为这些页面规格最稳定。
- 首页后半段不要急着精修，只先找方向图或占位图，等源站素材或 JSON 下来再定版。
- 所有 PC 和 Mobile 大图尽量分开导出，不要只给一张大图让前端裁。
- Logo、系列名、lockup 不要做进背景图里，能独立交付就独立交付。
- 商品图、swatch、badge 必须统一风格，否则列表页会显得很乱。
- 最终上线前要做一次“真实图片复核”：清晰度、压缩体积、主体位置、移动端裁切、文字可读性。
